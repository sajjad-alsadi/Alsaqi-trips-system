# الصيانة والتعديل

الملفان يُلصقان كما هما في مشروع Apps Script (لا نظام بناء). للمستودع اختبارات آلية على المنطق القابل للاختبار خارج Apps Script والمتصفح.

## تشغيل الاختبارات

```bash
npm install     # مرة واحدة: يثبّت jsdom (لاختبار الواجهة التفاعلي)
npm test        # أو: node --test
```

ما تغطيه: محرك الاحتساب (19 اختباراً)، كتابة المبلغ بالحروف، تصدير CSV، توحيد الأسماء والأرقام، **تطابق نسختي المحرك** بين الملفين، الوصول والأدوار و`setupFirstAdmin` (على محاكي Sheets في الذاكرة: `tests/helpers/fakeSheets.js`)، وسلامة صياغة الملفين. لا تغطي: سلوك Sheets الحقيقي (تحويل الأنواع والصيغ، القفل، الهوية) ولا عرض الواجهة؛ فهذه تبقى بقائمة الاختبار اليدوي أدناه.

- الاختبار الذي عنوانه «TODO» فجوة معروفة موثَّقة (يظهر «not ok # TODO» ولا يُفشل التشغيل).
- `tests/ui-smoke.test.js` يشغّل الصفحة في jsdom (الإكمال التلقائي والربط وتفريغ النموذج)؛ يُتخطّى إن لم يُثبَّت jsdom. وهو الذي كشف خطأ نطاق `DRIVER_PICKER` قبل أن يصل إلى النشر.
- فشل اختبار **التطابق** يعني أن أحد الملفين عُدِّل دون الآخر: عدّل الاثنين.
- عند إصلاح خلل: اكتب اختباراً يفشل أولاً، ثم أصلح، ثم تأكد أنه يمر.

## النسخة التجريبية (staging)

لا تجرّب تغييراً على الملف الحقيقي: **ملف ← إنشاء نسخة** (تُنسخ معه الشيفرة المرتبطة)، ثم انشر تلك النسخة كتطبيق ويب مستقل، وعرّف فيها مستخدمي التجربة، وجرّب عليها قائمة الاختبار اليدوي. بعد تحويل السكربت إلى مشروع مستقل (T2.8) تتغير الخطوات وتُحدَّث هنا.

## قواعد عند التعديل

1. **الاحتساب المشترك نسخة واحدة بنصين:** أي تعديل في `calcTrip_` أو `calcDays_` أو `pickRates_` أو `canonGov_` أو `nameKey_` أو `normId_` أو `parseLocal_` أو `GOV_ALIASES_` أو `GOVERNORATES_` أو `GRADES_` يُطبَّق في `src/google_apps_script.js` (من السطر 842) **وفي** `src/html_js_css.html` (بداية كتلة الجافاسكربت).
2. **الخادم هو المرجع:** لا تنقل ضابطاً إلى الواجهة وحدها؛ التحقق في الخادم إلزامي.
3. **لا تُغيّر أسماء أعمدة الشيتات** دون خطة ترحيل: الربط بالاسم (`readRows_` تبني الكائنات من نص الترويسة). الإضافة آمنة (`sheet_` يُكمل الناقص)؛ إعادة التسمية تُفقد الربط بالبيانات القائمة.
4. **ما صُرف لا يُمحى:** أي ميزة تعديل أو حذف جديدة يجب أن تمر بالتسويات (`addAdjustment_`) لا بالكتابة فوق «المصروف».
5. **كل إجراء كتابة يُسجَّل** بـ `appendLog_` ويعيد `patch` عبر `tripPatch_` ليحدّث العميل نفسه.
6. **عند الإصدار:** حدّث `APP_VERSION` و`EXPECTED_SERVER_VERSION` معاً و`CHANGELOG.md` (انظر `deployment.md`).
7. **الأنماط:** قواعد CSS العامة (مثل `.table-tools`) قد تتقدّم على الخاصة إن تساوت الخصوصية وتأخر ترتيبها؛ تحقّق من الترتيب عند أي إصلاح محاذاة.
